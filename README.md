# portfolio

榎本大貴（株式会社LITALICO 執行役員／LITALICO研究所 所長／AI統括部長、任意団体「みんなのアクセス」代表）の個人ポートフォリオサイトです。

公開URL: https://enochan.github.io/portfolio/

## 構成

ビルド不要の静的サイトです。

| ファイル | 内容 |
| --- | --- |
| `index.html` | サイト本体（HTML・CSS・JavaScript をすべて含む単一ファイル） |
| `events.json` | タイムラインに追加する項目（予定を含む）のデータ。ページが読み込み時に取得して表示します |
| `works.json` | 研究業績（論文・特許・受賞・書籍）。題名を確認できたものだけを書きます |
| `favicon.ico` / `apple-touch-icon.png` | ファビコン（ブラウザのタブ用、16・32・48px）と、スマホのホーム画面用アイコン（180px）。どちらも「みんなのアクセス」のロゴの Q! のマーク（文字なし）から作成 |
| `.nojekyll` | GitHub Pages で Jekyll の処理を無効にするための空ファイル |
| `llms.txt` | AI エージェント向けの案内（[llmstxt.org](https://llmstxt.org/) の形式）。人物の要約、主な活動、連絡方法、リンクを Markdown で書いています。公開URLは https://enochan.github.io/portfolio/llms.txt |

`index.html` のプロフィールやリンクを変えたときは、`llms.txt` も同じ内容に合わせて更新してください。

フォントは Google Fonts の「Zen Maru Gothic」を読み込んでいます。読み込めないときは、Hiragino Maru Gothic ProN、Hiragino Sans、Yu Gothic、Meiryo、sans-serif の順で使います。

## ローカルでの確認方法

`events.json` と `works.json` はページから `fetch` で読み込むため、`index.html` をブラウザで直接開く（`file://`）と、これらの項目は表示されません（HTML に書いた項目は表示されます）。すべて確認するときは、リポジトリ直下で簡易サーバーを起動します。

```sh
python3 -m http.server 8000
```

ブラウザで http://localhost:8000/ を開いてください。

## 更新の仕方

1. 登壇・掲載・記事を足すときは `events.json` に 1 件追加します。過去の項目は `index.html` に書かれたままです。同じ項目を両方には書きません。
2. 研究業績を足すときは `works.json` に、題名を確認できたものだけ追加します。学会発表の全件は複製しません。正本は [researchmap](https://researchmap.jp/denomoto) です。
3. ブラウザで表示を確認します。PC 幅とスマホ幅（390px 前後）の両方で、横スクロールが出ないこと、キーボード操作（Tab キー、絞り込みの左右キー）でフォーカス位置が見えることも確かめてください。
4. `main` ブランチにコミット・プッシュすると、数分で公開サイトに反映されます。

## タイムラインに項目を追加する（予定を含む）

リポジトリ直下の `events.json` に 1 件ずつ追加します。`index.html` を触る必要はありません。

### 手順

1. `events.json` を開きます。ファイル全体が 1 つの配列（`[` と `]`）で、その中に 1 件ずつ `{ … }` が並んでいます。
2. 配列の中に 1 件を追加します。1 件は 1 行で書き、前の項目の行末にカンマ（`,`）を付けます。最後の項目の後ろにはカンマを付けません。並び順は自由です（表示時に日付順に並べ替えます）。
3. `main` ブランチにコミット・プッシュします。数分で公開サイトに反映されます。

### 書き方の例

```json
[
  {"date": "2026-11-27", "type": "talk", "label": "研修", "title": "福祉事業所のAI導入と活用セミナー", "detail": "神奈川県後援・障害福祉サービス事業所の方向け／ユニコムプラザさがみはら"},
  {"date": "2026-12-10", "type": "write", "label": "執筆", "media": "note", "title": "記事タイトル", "url": "https://note.com/enomotod/n/xxxxxxxx"}
]
```

（2 件目は書き方の例です。実際の `events.json` には入っていません。）

必要なキーだけを書きます。任意のキーは、使わないときは書かずに省略します。

| キー | 必須 | 内容 |
| --- | --- | --- |
| `date` | 必須 | 日付。`YYYY-MM-DD` 形式（例：`2026-12-05`） |
| `type` | 必須 | 種類。`talk`（登壇・講座）、`write`（執筆・インタビュー）、`career`（経歴）のいずれか |
| `label` | 必須 | カードのバッジに出す文字（例：`登壇`、`講義`、`研修`、`ウェビナー`、`執筆`、`インタビュー`、`経歴`） |
| `title` | 必須 | タイトル。画面では年の見出し（h3）の下の h4 になります。`url` があるときは h4 の中のリンクになります |
| `detail` | 任意 | タイトルの下に出す補足（イベント名・会場など） |
| `media` | 任意 | 日付の横に出す媒体名（例：`note`、`Zenn`） |
| `url` | 任意 | 指定するとタイトルがリンクになります |

追加した後は、JSON として正しいかを確かめてください（例：`python3 -m json.tool events.json`）。エラーが出なければ形式は正しく書けています。

### 表示のされ方

- 「今日」は、閲覧者の端末の現地時刻ではなく、Asia/Tokyo の日付です。
- Asia/Tokyo の今日より **後** の日付の項目は「予定」として扱い、タイムラインの一番上の「これから」にまとめて表示します。日付が近い順に並び、カードには「予定」のバッジが付きます。見える日付は `2026年12月5日` のように年月日です。`<time datetime="2026-12-05">` は残します。
- Asia/Tokyo の今日と同じ日付、またはそれより前の日付の項目は、過去の項目として、該当する年の中に日付順で表示します。見える日付も同じく年月日です。その年の見出しがまだなければ自動で作られます。
- 日付がまだ取れないときは、項目を「これから」へ移しません。HTML に書いてある項目は出したままにします。
- 日付が過ぎると、書き換えなしで自動的に「これから」から年の中へ移ります。
- 予定が 0 件のときは「これから」は表示されません。
- 絞り込みは、`fieldset` と `legend` とネイティブのラジオボタンです。件数（例：「登壇・講座：10件を表示しています（うち予定1件）」）は、選んだときだけでなく画面に常に出ます。0 件のときは「該当する活動はありません」と、その外に「条件を戻す」を出します。
- `events.json` を読み込めなかったとき（JSON の書き方の誤り、通信エラーなど）は、画面に「追加の予定を表示できませんでした」と出します。`index.html` に書かれた既存の項目は通常どおり表示されます。日付やタイトルが欠けた項目は、その 1 件だけ表示されません。
- JavaScript が無効な環境では、`events.json` の項目は表示されません。
- ブラウザのキャッシュで古い内容が出ないよう、毎回サーバーに更新を確認して読み込みます。

既存の過去の項目は、これまでどおり HTML（`<div class="year">` の中の `<li data-type="…">`）に直接書かれています。月までの事実は `2020年10月` のように月まで、期間の「〜」もそのままです。日を足しません。

## 研究業績

`works.json` に、題名を確認できたものだけを置きます。種類は `paper`（論文）、`patent`（特許）、`award`（受賞）、`book`（書籍）です。画面の絞り込みは、`fieldset` と `legend` とネイティブのラジオボタン（すべて・論文・特許・受賞・書籍）です。英語だけの題名には `lang="en"` を付けます。題名の文言は変えません。

- 論文・受賞・書籍は `year` と `title`。特許は `number`（特許番号）と `title`。
- `people` に著者、`venue` に掲載先、`note` に補足を書きます。受賞の対象となった題名は `work` です。
- 査読ありと確認できた論文だけ `reviewed` を `true` にします。
- 確認できない特許や、推測した DOI は書きません。
- 読み込めなかったときは「研究業績を表示できませんでした」と出します。導入の文と、researchmap への案内は残ります。

## 表示の明暗

最初は OS の `prefers-color-scheme` に従います。この時点では `localStorage` に何も書きません。ヘッダーの「暗い表示にする」または「明るい表示にする」を押すと、`html` の `data-theme` と `localStorage` の `theme` に `dark` または `light` を保存し、次回からその表示に固定します。固定しているときは、ブラウザのテーマカラー（`meta name="theme-color"`）もその表示の背景色に合わせます。暗い表示で「コントラストを上げる」設定のときは、より暗い背景色に合わせます。「端末の設定に戻す」を押すと `localStorage` の `theme` を消し、OS の設定に戻します。

## お問い合わせ

連絡先は Google フォームの回答用リンク（`viewform`）だけにする予定です。URL はまだ決まっていません。URL 待ちなので、この変更はマージしないでください。

`index.html` の `a.gform` は2か所あります。`href` を入れる場所には TODO を書いてあります。URL が決まったら、その `href` に回答用 URL だけを書いてください。編集用 URL は書かないでください。新しいタブでは開かないので、`target` は付けません。

リンクの文字列は「お問い合わせフォームを開く（Google フォーム）」です。下線のあるリンクです。

メールアドレスと FormSubmit の送信先は、このブランチには書きません。
